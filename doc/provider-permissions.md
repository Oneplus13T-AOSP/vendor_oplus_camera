# Gallery provider permission compatibility (2026-11-09)

The manifest port patch removed OEM permission gates from eleven exported
Gallery providers. At least MultiProcessSpProvider has no additional caller
permission check in query/insert/update: it reads and writes Gallery preferences.
Removing its manifest gate exposes those operations to unrelated apps. A
read-only shell content query for a nonexistent key also reached this provider
on the connected phone; no settings were changed by that probe.

Replace these eleven OEM provider gates with the platform permission
android.permission.WRITE_MEDIA_STORAGE (signature|privileged). Both
com.oplus.camera and com.coloros.gallery3d already request this permission and
are granted it by this port's system_ext allowlist, preserving their integration.
Other apps must have this platform permission or an explicit URI grant, where
supported. This change does not restrict the normal public photo-view/share
activities, and it does not claim a complete security audit of the stock APKs.

Validation: reversed the previous manifest patch against the decoded cached APK,
applied the revised patch and compared the entire manifest to the rebuilt input.
The rebuilt APK's binary manifest contains all eleven gates. All 1959 DEX,
native-library and asset entries retain identical uncompressed contents.
The generated ignored camera/proprietary/system_ext/priv-app/OppoGallery2 APK
must be refreshed with the patch, or regenerated by extraction. A ROM build
will sign it with the platform certificate as before. No APK was installed on
the phone; camera-to-gallery view/edit, sharing, and Live Photo need a runtime
retest after updating the ROM.
